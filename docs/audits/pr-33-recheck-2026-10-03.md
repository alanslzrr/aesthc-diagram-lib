## Remaining findings and required solutions

### N01 · P2 — Re-resolving does not invalidate cached font widths

Locations: `src/editor/index.tsx:87,759–793`; `src/geometry/text.ts:33–52`.

The new `fontsReady` state rebuilds scene resolution but keeps the module-level `measureText` function and its cache. The cache key has no font-load generation. Every already-measured string returns its pre-Geist width.

**Independent browser reproduction:** using the actual `createCanvasTextMeasurer` implementation, measure `WWW payment.succeeded` at 20 px before loading Geist, then load the real bundled WOFF2:

- Before: **241.19140625 px**.
- Same measurer after `document.fonts.ready`: **241.19140625 px**.
- Fresh measurer after loading: **245.1798858642578 px**.
- `document.fonts.check('20px Geist')`: **true**.

This demonstrates an uncorrected cache path. CI independently still fails the Band ES pill padding test. It does not prove that every CI glyph discrepancy has only this cause.

**Fix:** explicitly load/check the two required font faces; renew or invalidate the measurer cache when the font environment changes, and supply that measurer identity/generation to committed and preview resolution. Handle late host font registration and unmount cleanup. `FontFaceSet.status === 'loaded'` alone is not proof the required faces were loaded.

**RED → GREEN:** delay both font responses; record an initial fallback measurement; release fonts; assert changed measured widths, rebuilt pill bounds, and text padding in both themes/locales at 50/100/200%. Keep the current padding floor. Repeat with a second editor instance and during/after a gesture.

### N02 · P2 — Malformed renderer results still escape or export corrupted content

Locations: `src/editor-core/scene.ts:276–323`; `src/editor-core/renderers.ts:60–99`.

The code catches exceptions thrown inside callbacks, but reads return values outside those guarded boundaries. The scene pipeline also bypasses the helper's non-empty SVG-string check.

**Fresh built-public-API counterexamples:**

| Renderer result             | Observed `exportDocument` outcome                         |
| --------------------------- | --------------------------------------------------------- |
| `validate()` returns `null` | Throws: cannot read `ok`                                  |
| `measure()` returns `null`  | Throws: cannot read `width`                               |
| `renderSvg()` returns `''`  | Returns success and falls back to ordinary node rendering |
| `renderSvg()` returns `{}`  | Returns success; SVG contains literal `[object Object]`   |

These violate the claimed defensive boundary even though they originate in a trusted renderer. TypeScript types cannot enforce JavaScript plugin output at runtime. The scene comment explicitly promises malformed-return isolation.

**Fix:** validate callback result shapes before property access; enforce finite positive dimensions and a non-empty SVG string through one shared path. Convert callback failures and invalid results to subject-bearing diagnostics. Keep the node subject when an export forwards an error instead of replacing the full diagnostic with `failure(code)`.

**RED → GREEN:** table-driven null/undefined/wrong-shape/empty-string/non-string/throw cases for registry helper, resolver, SVG/HTML/cards and supported WebM. Exports must fail explicitly, unrelated nodes/instances must remain usable, and no corrupt successful artifact may be produced.

### N03 · P2 — Frozen payload is cast, not validated; failure hides the usable fallback

Locations: `src/export/standalone.tsx:23–32,69–92`.

The new `aesthc-frozen` JSON is parsed and cast directly. `Object.keys`/`Object.values` assume its shape. The static fallback is hidden before the registry/runtime has been constructed successfully.

**Browser reproduction:** take the actual newly generated custom HTML, replace only the frozen-data script contents with the valid JSON literal `null`, and open it. Result:

- `#aesthc-fallback.hidden === true`;
- no `.adl-viewer`;
- blank page;
- uncaught `TypeError: Cannot convert undefined or null to object`.

This is a corrupt-artifact robustness failure, not a claim that the unmodified happy-path export is blank or that script execution was exploited.

**Fix:** validate the frozen map, own keys, node/type correspondence, finite positive bounds, SVG strings, count/byte limits and the portable SVG policy. Construct the registry before changing visibility; preserve the static fallback with a visible diagnostic on any validation/mount failure. Avoid hiding it until a successful runtime handoff. Use bounded indexed lookups rather than scanning all frozen nodes for every type resolution.

**RED → GREEN:** null/array/wrong-shaped entry, unknown node/type, missing data, malformed JSON and invalid dimensions all retain a readable fallback without page errors. Valid multi-node, same-type, distinct-type artifacts remain correct with JS on/off and CSP/offline checks.

### N04 · P2 — Shared export still cannot carry an instance registry

Locations: `site/src/lib/export-service.ts:124–135,175–189,237–245,264,286–291`; `site/src/components/ExportDialog.tsx`.

Viewer card/WebM/publish handlers now pass their registry. The shared Playground/Studio export context still has no registry field and forwards none to SVG/raster, HTML, cards or WebM. This part of V05 was not fixed by adding `appearance`.

**Fix:** carry the same trusted instance registry used for display through the shared dialog/service and all relevant public calls. Consolidate Viewer controls onto that context where planned, or explicitly retain a tested equivalent adapter. Do not add a global registry or serialize executable callbacks.

**RED → GREEN:** render and export a custom node through the actual shared UI; verify geometry/artifact content. Two simultaneous instances with the same typeKey but different implementations must remain isolated. Missing registries must produce a visible error rather than a misleading success.

## Key Learnings

1. Re-resolving geometry cannot fix font widths while the underlying measurer returns stale cached values.
2. Catching callback exceptions is not equivalent to validating callback return values.
3. A portable viewer should keep its readable fallback until all runtime data is validated and startup succeeds.
