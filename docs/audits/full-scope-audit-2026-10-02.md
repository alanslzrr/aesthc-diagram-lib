# Full-scope product and library audit

Date: 2026-10-02. Language: English. Verdict: **not approved as a complete, polished delivery**.

This audits the existing working tree, not just the last pasted status report and not the already-published npm artifact. The base commit is `a7d8e246f426dfec660e0caeb15a7e9e10111e4b`; substantial uncommitted changes were present before the audit. No implementation fixes, baseline updates, commits or publication were performed. Only audit documents/evidence were added.

## Executive assessment

The work is substantially further along than the previous reports imply in some places: **Heyo really is mounted now**, the supplied visual comparisons pass, and the earlier resize-marker and geometry-test corrections exist. It would be inaccurate to repeat those old findings as unresolved.

Nevertheless, successful existing tests do not establish complete acceptance. Additional probes and live Agent Browser interactions found illegal locked-node edits, invalid optimized previews, lost edits during conversion, broken saved-copy identity handling, incomplete portable-export policy and incomplete interactive customization. These are not cosmetic disagreements.

The visual direction is recognizably closer to the requested Geist/Vercel system. The remaining premium-quality problem is primarily **consistency, legibility, responsive workspace allocation and complete workflows**, not simply choosing a different font or dark background again.

This guide records **33 findings/acceptance issues (F01–F33), two test defects (Q01–Q02), six capability gaps (G01–G06), and seven design workstreams (D01–D07)**. Some workstreams overlap intentionally; they are not 48 independent runtime bugs. Evidence type and severity are stated per item.

### Evidence labels

- **B**: reproduced through the live Agent Browser interface.
- **P**: reproduced by an executed source/public-API probe or artifact inspection.
- **S**: confirmed by source/API inspection; the failure interaction was not separately executed.
- **G**: product/design gap relative to the requested complete experience, not a claim that the underlying API is absent.
- **U**: unresolved or not verified. Never count this as passing.

P1 blocks complete acceptance. P2 requires correction but is not automatically a release-blocking security issue. Do not call a lock failure an authorization-system bypass; do not call an unsafe preview URL executed XSS; neither was demonstrated.

## 2. Blocking functional findings

### F01 — P1 · Replacement commands bypass node locks · B/P

**Location:** [commands.ts](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/editor-core/commands.ts:51), [store.ts](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/editor-core/store.ts:430). Contract: [04-contracts.md](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/docs/specs/editable-canvas/04-contracts.md:48).

`scene.set` can move a locked node or clear its lock without the explicit unlock command. `document.replace-content`, used by Apply JSON, changes locked geometry/content. These probes commit and create history. Live Studio reproduction: lock Web client, change its label in JSON, Apply JSON; the label changes while the control still says Unlock.

**Solution:** Validate the transition from the trusted baseline to the candidate, not only the candidate schema. Apply lock invariants across scene replacement, content replacement, previews and mixed batches. Support direct and inherited group locks. Keep explicit permitted unlock-then-edit and explicit new-document Import/Open flows valid.

**Required regression:** direct/group lock × move/delete/relabel/replace × preview/commit; rejected operations preserve document, last-good draft, selection, history and notifications. Include explicit unlock success.

### F02 — P1 · Apply JSON silently changes session type/identity · P

**Location:** [commands.ts:51](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/editor-core/commands.ts:51). Contract: [04-contracts.md:42](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/docs/specs/editable-canvas/04-contracts.md:42).

A valid Timeline document is accepted into a Graph session as an ordinary content edit. A foreign document ID is silently overwritten with the current ID. The contract explicitly separates same-document Apply JSON from cross-type Import/Convert.

**Solution:** Enforce compatible format/schema/id/type on content replacement and return stable diagnostics. Use the explicit confirmed new-document workflow for import/conversion; do not silently normalize identity.

**Required regression:** same ID/type success, foreign ID rejection, foreign type rejection, stale draft rejection; explicit import still works. Update test harnesses that currently use Apply JSON as an undocumented import shortcut.

### F03 — P1 · Optimized previews can replace valid state with invalid data · P

**Location:** [store.ts:26–96](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/editor-core/store.ts:26), [store.ts:419](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/editor-core/store.ts:419).

The public `skipValidation:true` preview path accepts `presentation.textScale=NaN` and metadata containing a `javascript:` URL. It returns success and replaces the last-good preview; subsequent full validation fails. Ordinary drag is not claimed to produce these values, and URL execution was not demonstrated.

**Solution:** Permit the fast path only for an explicit set of completely delta-validated commands. Fully validate all other or mixed batches. Consider making the optimization internal rather than a general host-controlled escape hatch.

**Required regression:** every command variant, mixed scene/metadata operations, NaN/Infinity, palette/grid ranges and dangling references. Assert that rejected input never reaches preview subscribers and that prior preview identity/content survives.

### F04 — P1 · Conversion confirmation destroys intervening edits · B

**Location:** [Studio main.tsx:300–315](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/site/src/studio/main.tsx:300), [595–623](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/site/src/studio/main.tsx:595).

Opening Convert to graph captures an old converted snapshot. The nonmodal notice leaves editing available. Confirmation passes the latest revision rather than the revision used to generate the snapshot. Browser sequence: import Band → open conversion → change label → confirm. The new label disappears and Undo is disabled.

**Solution:** Bind the pending conversion to `{documentId, baseRevision}`. Invalidate it on edits/replacement, or recompute and ask for confirmation again. Never authorize stale content using a freshly read revision.

**Required regression:** intervening edit, undo, import, type switch and cancellation. Stale confirmation must be a no-op with an explanation; valid confirmation remains explicit and resets history only as documented.

### F05 — P1 · Saved copies use the wrong key/token when reopened · P/S

**Location:** [Studio main.tsx:120–143](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/site/src/studio/main.tsx:120), [200–215](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/site/src/studio/main.tsx:200), [330–388](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/site/src/studio/main.tsx:330).

Save as writes `saveas:<slug>` while keeping `document.id`. Opening it stores the copy's token. Save locally and autosave still address `document.id`, so the token and key no longer describe the same record. A built-public-API reproduction returns a conflict after save original → save copy → open copy → edit → save using the current wiring.

**Solution:** Introduce an explicit active storage key independent of document identity. Switch key, token, conflict state and autosave ownership atomically. State whether Save as activates the copy or only creates an archival copy.

**Required regression:** reopen/edit/save/reload the copy, original unchanged; autosave writes only the active key; conflict and quota failures preserve both copies and the local draft.

### F06 — P1 workflow · Playground work is abandoned on navigation · B/S

**Location:** [PlaygroundApp.tsx:124–153](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/site/src/playground/PlaygroundApp.tsx:124), [249–323](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/site/src/playground/PlaygroundApp.tsx:249).

The per-example store Map correctly preserves internal switching, but is only in memory. Full Studio opens a separate demo, not the edited document; leaving/reloading has no corresponding dirty/draft protection. Browser verified that an edited Band survives example switching but not leaving and returning, and that Full Studio opens an unrelated Graph.

**Solution:** Provide explicit current-document handoff and local draft recovery, plus guards for dirty documents and uncommitted text. If Studio intentionally opens an independent workspace, label that and do not present it as the path to exporting the current work.

**Required regression:** switch examples, same-tab navigation, reload, browser back, valid/invalid text draft, failed recovery storage and explicit discard. Do not serialize private documents into unbounded URL parameters as a shortcut.

### F07 — P1 · “Minimal” offline exports include excluded metadata · P

**Location:** [html.ts:51–55](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/export/html.ts:51). Contract: [05-boundaries.md:27](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/docs/specs/editable-canvas/05-boundaries.md:27).

A real HTML artifact made with bundled runtime/fonts and `includeSource:false` still contains synthetic private edge notes, links and arbitrary extension data. Node notes are removed, edge notes are not. `includeSource:false` alone is not a promise of full redaction, but the documented minimal metadata policy is still violated.

**Solution:** Use one allowlisted metadata projection for portable artifacts, handling nodes and edges consistently. Define/preserve required viewer semantics and implement explicit all-metadata opt-in. Keep optional canonical source separate from runtime data.

**Required regression:** unique sentinel per excluded field; inspect every embedded payload, not just visible markup or the receipt. Test minimal/all and source off/on independently.

### F08 — P1 · WebM setup failures leak or never settle · P

**Location:** [motion.ts:78–101](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/export/motion.ts:78), [166–180](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/export/motion.ts:166).

Controlled platform probes show: a throwing MediaRecorder constructor leaves tracks unstopped; a throwing `start()` while inactive enters cleanup awaiting an `onstop` that never occurs. The returned promise remains unresolved. These are induced platform failures, not claims of a real browser codec crash.

**Solution:** One guarded acquisition/recording/release lifecycle; track allocated resources and successful start separately. Never wait for an inactive recorder's impossible event. Settle abort/error paths during image loading, recording and stopping; enforce finite options/resource limits before allocation.

**Required regression:** constructor/capture/start/asynchronous recorder failures and cancellation at each phase. Every promise settles, every acquired track stops, object URLs release and canvas backing memory is cleared.

### F09 — P1 · Deployment-profile rules are not enforced consistently · P

**Location:** [profiles.ts:23–30](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/editor-core/profiles.ts:23), [export/index.ts:153–161](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/export/index.ts:153). Contract: [05-boundaries.md:92](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/docs/specs/editable-canvas/05-boundaries.md:92).

An authored `engineeringProfile='deployment-ownership'` is ignored unless enabled separately. Canonical publish succeeds even though explicit profile validation reports missing ownership. Region accounting uses tags instead of ancestor region groups; other external/public/security-group rules diverge from the declared contract.

**Solution:** Centralize activation and exact rules, and invoke them from all publish entrypoints. Do not depend on a demo UI checkbox to enforce an authored document policy.

**Required regression:** authored activation through save/load/share/HTML, invalid enabled profile blocking publish, ancestor regions, external-owner exception, database/storage visibility, security groups and crossing metadata. Any scope reduction requires an explicit decision, not a renamed passing test.

### F10 — P1 completeness gap · Custom renderers stop at headless APIs · S/G

**Location:** [EditorRoot/Surface](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/editor/index.tsx:75), [DiagramViewerProps](/Users/alansalazar/development-projects/personal-proyects/aesthc-diagram-lib/src/viewer/DiagramViewer.tsx:33).

The registry works for headless resolution/export, but public editor/viewer components have no per-instance registry input and resolve without it. Cards/HTML/motion have no coherent custom-renderer delivery contract either. A registered headless renderer does not make that node editable/viewable through the supplied components.

**Solution:** Thread a per-instance render context through resolution, previews, measurement, rendering and supported export paths. Define offline behavior explicitly: trusted bundled renderer versus frozen canonical geometry; fail unsupported delivery with a diagnostic.

**Required regression:** two packaged editors/viewers registering the same key differently; render/edit/resize/undo/export without cross-instance contamination or placeholder fallback. Include registry changes and cache invalidation.
